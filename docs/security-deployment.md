# 安全部署指南

## 适用边界

DocWeave 当前定位为单实例文档处理工具，没有用户认证、授权、租户隔离和公网限流能力。默认 Compose 仅监听 `127.0.0.1`。如需多人访问，应置于可信 VPN、反向代理身份认证和防火墙限源之后；未完成这些控制前不得直接暴露到公网。

上传的 PDF、翻译记忆、术语、任务日志和生成结果都可能包含敏感业务信息。部署者负责获得文档处理授权，并确认 MinerU 与 LLM 服务的数据保留、训练使用、地域和合规条款。

## 网络与密钥

- LLM 服务应使用可信 HTTPS 地址。开发机上的环回 HTTP 服务仅限本机调试；远程 HTTP 默认被拒绝，仅可信隔离网络可显式设置 `DOCWEAVE_ALLOW_INSECURE_LLM_HTTP=true`。
- `.env` 只保存在部署机上，权限应限制为服务账户可读，不得进入镜像、Git、日志或问题报告。
- 不要在 URL 中携带用户名、密码或令牌；API Key 仅通过 `LLM_API_KEY` 注入。
- `DOCWEAVE_BIND_ADDRESS` 默认保持 `127.0.0.1`。可信内网部署应填写明确私网地址，不建议使用 `0.0.0.0`。
- 反向代理应配置 TLS、身份认证、请求速率限制、上传大小限制和访问日志脱敏。

## 文件与数据

- `DOCWEAVE_DATA_DIR` 应指向项目独立目录，并由运行账户独占读写。
- 不要把生产目录挂载到开发或测试容器，也不要使用真实文档作为单元测试夹具。
- SQLite 数据库、上传文件和结果文件应纳入加密备份；恢复演练应在隔离环境执行。
- 删除任务目前只取消未完成处理，不等同于安全擦除文件或数据库内容。涉及数据保留期限时，应另行建立经过审核的清理流程。

## 容器与运行时

- 后端镜像以非 root 用户运行；不要覆盖为 root。
- 上线前固定镜像摘要并扫描基础镜像和系统包漏洞。
- 为容器设置 CPU、内存、进程和磁盘配额，防止恶意或异常 PDF 耗尽资源。
- 生产环境关闭调试和自动重载，不向客户端返回堆栈或上游响应正文。

## 发布检查

1. 执行后端测试、前端构建、Bandit、pip-audit 和 pnpm audit。
2. 扫描当前文件及完整 Git 历史中的凭据、真实服务地址、个人信息和业务数据。
3. 核对配置、数据备份、回滚版本、外部服务可用性、网络策略和健康检查。
4. 确认许可证、第三方依赖许可证及安全报告渠道已经生效。
